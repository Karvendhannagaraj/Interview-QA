For a mid-level developer, what we covered is enough.

For a senior developer, there are a few more important HTTP concepts that interviewers often expect you to know.


---

1. Safe vs Idempotent vs Cacheable

Many developers know CRUD mapping but get confused here.

Method	Safe	Idempotent	Cacheable

GET	✅	✅	✅
HEAD	✅	✅	✅
OPTIONS	✅	✅	Usually
PUT	❌	✅	❌
PATCH	❌	Usually	❌
DELETE	❌	✅	❌
POST	❌	❌	Usually No


Safe

No data modification.

Example:

GET /products

Only reads.


---

Idempotent

Same request multiple times = same final state.

Example:

PUT /users/1

Run 1 time or 100 times.

Result remains same.


---

Cacheable

Response can be stored.

Example:

GET /products

Browser/CDN can cache.


---

2. REST API URL Design

Bad:

POST /createUser
POST /deleteUser
POST /updateUser

Good:

POST /users
GET /users
GET /users/1
PUT /users/1
DELETE /users/1

Interviewers love asking:

> "How would you design a User API?"




---

3. Content Negotiation

Client can ask for specific response format.

Request:

Accept: application/json

or

Accept: application/xml

Server responds accordingly.


---

4. Important Request Headers

Authorization

Authorization: Bearer JWT_TOKEN

Authentication.


---

Content-Type

Content-Type: application/json

Tells server request body format.


---

Accept

Accept: application/json

Expected response format.


---

Origin

Used in CORS.

Origin: https://example.com


---

5. Important Response Headers

Cache-Control

Cache-Control: max-age=3600

Cache for 1 hour.


---

Location

After creation:

HTTP/1.1 201 Created
Location: /users/101

Senior interview favorite.


---

Access-Control-Allow-Origin

Access-Control-Allow-Origin: *

CORS.


---

6. Conditional Requests

Reduce unnecessary downloads.

Browser sends:

If-Modified-Since

or

If-None-Match

Server returns:

304 Not Modified

No need to resend data.


---

7. ETag

Resource fingerprint/version.

Response:

ETag: "abc123"

Later:

If-None-Match: "abc123"

If unchanged:

304 Not Modified

Very common in scalable systems.


---

8. Rate Limiting

Protect APIs.

Response:

429 Too Many Requests

Headers:

X-RateLimit-Limit
X-RateLimit-Remaining

Example:

100 requests/minute



---

9. API Versioning

URL Versioning

/api/v1/users
/api/v2/users

Most common.


---

Header Versioning

Accept: application/vnd.company.v2+json

Less common.

Interview Question:

> How do you release breaking API changes?



Answer:

> API versioning.




---

10. Authentication vs Authorization

Most frequently asked question.

Authentication

Who are you?

401 Unauthorized

Token missing/invalid.


---

Authorization

Can you do this?

403 Forbidden

Permission denied.


---

11. HTTP vs HTTPS

HTTP

http://

Plain text.


---

HTTPS

https://

Encrypted using TLS/SSL.

Senior interviews almost always ask:

> Why HTTPS?



Answer:

Encryption

Integrity

Authentication



---

12. CORS Deep Understanding

Browser sends:

OPTIONS

Preflight request.

Server responds:

Access-Control-Allow-Origin
Access-Control-Allow-Methods
Access-Control-Allow-Headers

Then actual request is sent.

Question:

> Why doesn't Postman face CORS issues?



Answer:

> CORS is enforced by browsers, not by servers or Postman.

14. Retryable Requests

Good candidate for retry:

GET
PUT
DELETE

Usually avoid automatic retry:

POST

Reason:

POST /orders

Retry may create duplicate orders.


---

15. HTTP Interview Question That Surprises Seniors

Why is PUT idempotent but POST is not?

PUT:

PUT /users/1

Resource already identified.

Final state remains same.

POST:

POST /users

Every call may create a new resource.
